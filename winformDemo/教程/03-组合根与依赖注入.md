# 03 · 组合根与依赖注入

**目标**：逐行读懂 `Program.cs`，理解「谁创建对象」「对象活多久」「为什么业务代码里看不到 `new`」。

## 1. 什么是组合根（Composition Root）

**组合根 = 应用启动时唯一负责把接口和具体实现拼在一起的地方**。本项目的组合根就是 `Program.Main`。

为什么需要"唯一"？因为如果每个类都自己 `new` 依赖：

```csharp
// 反例
public class MainForm : Form {
    private readonly ModbusRtuClient _client = new ModbusRtuClient(); // 绑死了
}
```

换成模拟设备、换数据库、写单元测试，都要改这个类。而集中装配后，替换只需要改组合根的一行。

## 2. 逐行读 `Program.cs`

```csharp
[STAThread]
private static void Main(string[] args)
{
    ApplicationConfiguration.Initialize();          // WinForms 高 DPI / 默认字体

    var builder = Host.CreateApplicationBuilder(new HostApplicationBuilderSettings
    {
        ContentRootPath = AppContext.BaseDirectory, // 配置从程序目录读，不受工作目录影响
        Args = args                                 // 命令行参数也进配置系统
    });
    builder.Configuration.AddJsonFile("appsettings.json", optional: false, reloadOnChange: false);

    builder.Services.Configure<AppOptions>(builder.Configuration.GetSection("App"));
    builder.Services.AddSingleton<IModbusClient, SimulatedModbusClient>();
    builder.Services.AddSingleton<ICalibrationService, CalibrationService>();
    builder.Services.AddSingleton<IMeasurementRepository, JsonMeasurementRepository>();
    builder.Services.AddSingleton<AcquisitionService>();
    builder.Services.AddHostedService(sp => sp.GetRequiredService<AcquisitionService>());
    builder.Services.AddTransient<MainForm>();

    // ... self-test 分支 ...

    using var host = builder.Build();
    var form = host.Services.GetRequiredService<MainForm>();
    host.Start();
    Application.Run(form);
    Task.Run(() => host.StopAsync()).GetAwaiter().GetResult();
}
```

**四段式**：建 builder → 注册服务 → `Build()` → `Start()` / 运行 UI / `StopAsync()`。

### 生命周期

| 注册方式 | 含义 | 本例 |
|---|---|---|
| `AddSingleton<TInterface, TImpl>` | 全应用一个实例 | 设备客户端、标定服务、仓储、采集服务 |
| `AddTransient<T>` | 每次解析都新建 | `MainForm`（只解析一次，所以实际也只有一个） |
| `AddHostedService` | 由 Host 负责 Start/Stop 的后台任务 | `AcquisitionService` |

📌 **为什么 `AcquisitionService` 注册了两次？** 它既要是**单例**（`MainForm` 要订阅它的 `BatchArrived` 事件，必须拿到同一个对象），又要是**托管服务**（由 Host 调 `StartAsync/StopAsync` 管理生命周期）。`AddHostedService(sp => sp.GetRequiredService<AcquisitionService>())` 用工厂从容器里取那个单例，保证两者是同一个实例。

> 如果写成 `AddHostedService<AcquisitionService>()`，容器会另外创建一个实例，`MainForm` 订阅的和后台运行的不是同一个对象——事件永远收不到。这是 DI 里非常经典的坑。

### 构造函数注入

```csharp
// Presentation/MainForm.cs
public MainForm(
    AcquisitionService acquisition,        // 容器自动填
    IMeasurementRepository repository,     // 容器自动填
    ILogger<MainForm> logger)              // 容器自动填
```

`MainForm` 只声明"我需要什么"，不关心"从哪来、怎么创建"。容器递归解析依赖树：`MainForm → AcquisitionService → (IModbusClient, ICalibrationService, IOptions<AppOptions>, ILogger<T>)`。

📌 **服务定位器反模式**：除了组合根，任何地方出现 `Services.GetRequiredService<...>()` 都要警惕——它把依赖藏起来，让类无法独立测试。构造函数注入让依赖**显式可见**。

### 为什么用 `Task.Run` 包住 `StopAsync`

`host.StopAsync()` 内部有 `await`，会捕获当前线程的 `SynchronizationContext`（WinForms 的 UI 上下文）。如果在 UI 线程上 `.GetAwaiter().GetResult()` 同步等待，continuation 又要回到同一个 UI 线程 → **死锁**。丢到线程池执行就没有 UI 上下文，安全退出。WPF 版本用了完全相同的处理，第 09 章还会对照。

## 3. 对照旧项目

| 旧项目 `Form1.cs` | 本骨架 |
|---|---|
| `private totalView totalView = new totalView();` 字段初始化器 | 组合根统一注册 |
| 页面在用户点击前就被构造（连带读配置文件，缺失即崩） | 启动时集中装配、集中报错 |
| `new mainView(uiLight1)` 把主窗体控件引用传进子页面 | 依赖通过构造函数注入，页面之间不互相持有控件 |
| 静态 `mainCommon` 充当"全局服务容器" | 真实的 DI 容器，有生命周期、可替换、可 dispose |

## 🧪 动手实验

**实验 3.1 · 制造「两个实例」的经典 bug**
把 `AddHostedService(sp => sp.GetRequiredService<AcquisitionService>())` 改成 `AddHostedService<AcquisitionService>()`，运行。预期：界面数据不再刷新。原因：`MainForm` 订阅的单例没有在跑，跑起来的那个托管实例没人订阅。改回来。

**实验 3.2 · 换成 Transient 会怎样**
把 `IModbusClient` 的注册从 `AddSingleton` 改成 `AddTransient`，运行并观察。预期：采集服务与自检可能拿到不同实例；对无状态模拟设备影响不大，但真实设备会出现"两个实例抢同一个串口"。这能让你记住：**有状态/占用资源的依赖必须是 Singleton**。

**实验 3.3 · 加一个从没被用过的服务**
写一个小类 `HelloService`，在组合根 `AddSingleton<HelloService>()`，但不注入任何地方。在 `MainForm` 构造函数加一个参数 `HelloService hello`，运行。预期：正常启动，说明容器能递归解析任意深度的依赖树。

**实验 3.4 · 故意删掉一个注册**
注释掉 `AddSingleton<ICalibrationService, CalibrationService>()`，`dotnet build` 应该仍然通过，但运行 `--self-test` 会抛 `InvalidOperationException: Unable to resolve service...`。体会「编译期不报错、运行期才暴露」的 DI 特点，以及为什么自检模式很有价值。

## 自测

1. `AddSingleton` 和 `AddTransient` 的区别是什么？为什么 `AcquisitionService` 必须是单例？
2. 除了组合根，还有哪里可以用 `GetRequiredService`？为什么不建议？
3. `host.Start()` 和 `Application.Run()` 各自负责什么？顺序能颠倒吗？

<details><summary>答案要点</summary>

1. 单例全应用共享、Transient 每次新建；事件订阅要求订阅方与发布方是同一实例。
2. 技术上任何能拿到 `IServiceProvider` 的地方都行，但那是服务定位器，隐藏依赖且难测试；应只在组合根使用。
3. `Start()` 启动托管服务（后台采集），`Application.Run()` 启动 UI 消息循环；先启动服务再进消息循环，保证窗口一出现就有数据；颠倒会导致窗口先显示、数据晚到，甚至服务发布事件时还没有订阅者（不过本项目订阅发生在 MainForm 构造，早于 host.Start，所以不会丢事件）。

</details>
