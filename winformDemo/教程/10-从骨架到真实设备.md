# 10 · 从骨架到真实设备（第一套收尾）

**目标**：拿到一张「毕业清单」——知道把这套骨架变成产线可用的上位机，还要补哪些东西、按什么顺序补。

## 1. 换真实硬件：只动 Infrastructure + 一行注册

把 `SimulatedModbusClient` 换成基于 NModbus 的实现：

```csharp
// Infrastructure/NModbusClient.cs（示意，不在骨架里）
public sealed class NModbusClient : IModbusClient
{
    private readonly SerialPort _port;
    private IModbusSerialMaster? _master;
    private readonly AppOptions _options;

    public async Task ConnectAsync(CancellationToken ct) { /* 打开串口、创建 RtuMaster */ }
    public async Task<ushort[]> ReadChannelsAsync(CancellationToken ct) {
        // 0x03 功能码：起始地址 0，读 ChannelCount 个保持寄存器
        return _master!.ReadHoldingRegisters(slaveId, 0, (ushort)_options.ChannelCount);
    }
    public void Dispose() { _master?.Dispose(); _port?.Dispose(); }
}
```

组合根改一行：

```csharp
builder.Services.AddSingleton<IModbusClient, NModbusClient>();
```

要补的工程细节（按重要性）：

| # | 事项 | 原因 |
|---|---|---|
| 1 | 串口参数（COM 口、波特率、从站地址）进 `appsettings.json` | 现场可改，不用重新编译 |
| 2 | 读超时 + 重试 + 退避（如 3 次 / 指数退避） | 现场干扰常见，不能每次抖动都刷日志 |
| 3 | 连接状态事件 `ConnectionChanged` | 界面要显示「已连接/断开/重连中」 |
| 4 | 字节序 `ABCD/CDAB/BADC/DCBA` 配置化 | 不同厂商设备不同 |
| 5 | 断线自动重连，但**不要**在后台线程读 UI 控件取 COM 名 | 旧项目的坑 |
| 6 | `Dispose` 里真正关闭串口 | 避免下次启动端口被占 |

## 2. 换真实数据库：只动 Infrastructure + 一行注册

`SqliteMeasurementRepository` 的要点（第 08 章已列清单）：

- 构造函数 `CREATE TABLE IF NOT EXISTS`（旧项目把 `InitDatabase()` 注释掉，是干净环境崩溃的根因）；
- 字段类型用 `INTEGER`/`REAL`/`TEXT(ISO8601)`，不要把数值存成字符串；
- 参数化 SQL，动态 WHERE 只拼条件片段、值一律走参数；
- 时间统一 `yyyy-MM-dd HH:mm:ss` 或 ISO 8601，保证字符串排序等价于时间排序；
- `AddAsync` 回填自增 Id（`last_insert_rowid()`）；
- 高频写入用事务或批量提交。

## 3. 把 Core 拆成独立类库（真正的"企业级"）

现在 `Core` 只是**一个文件夹**，编译器其实不阻止你在里面 `using System.Windows.Forms`（第 02 章实验 2.1 已验证）。要强制分层，把每个目录拆成类库项目：

```
WinformDemo.sln
├── EnterpriseDemo.Core           （类库，无任何 UI/第三方依赖）
├── EnterpriseDemo.Infrastructure （类库，引用 Core）
├── EnterpriseDemo.Application    （类库，引用 Core）
└── WinformDemo.Presentation      （WinExe，引用以上三个 + Hosting 负责装配）
```

好处：**编译器替你守住依赖方向**；业务层可以被 WPF、Web API、单元测试项目同时引用。下一步学 WPF 时，你就能把前三个类库**原封不动复用**，只新建一个 WPF 表现层项目。

## 4. 单元测试清单（优先测这些）

| 测什么 | 为什么 | 怎么测 |
|---|---|---|
| `CalibrationService.Convert` | 业务核心，端点/中间值/非法配置 | `Options.Create(new AppOptions{...})` + `NullLogger<T>.Instance` |
| 判定边界（= 上限、= 下限） | `>=`/`<=` 容易写错 | 构造 `ChannelReading` 断言 |
| `JsonMeasurementRepository` | 落盘/重启/损坏降级 | 临时目录 + 独立实例 |
| 字节序转换 | 换设备后最容易出错 | 已知浮点数的四种排列 |
| `AcquisitionService` 取消 | 关闭时不卡死 | `CancellationTokenSource` + 短间隔 |

📌 因为这些类都只依赖接口与 BCL，**不需要开窗口、不需要真设备**就能测——这就是前 9 章所有设计决定的最终回报。

## 5. 还缺的生产特性（按优先级）

2. 报警记录、不合格追溯、导出 CSV/Excel
3. 趋势曲线（ScottPlot）、历史分页查询
4. 用户权限、操作审计
5. 日志落文件 + 滚动清理（Serilog/NLog）
6. 多语言、DPI 自适应、主题
7. 安装包（MSIX/ClickOnce）与自动升级
8. 配置热更新（`IOptionsMonitor<T>` / `reloadOnChange: true`）

<details><summary>答案要点</summary>

1. 理想情况下只新增 WPF 的表现层文件 + 一个新的组合根；`Core`/`Infrastructure`/`Application` 零改动。下一套会实证。
