# 01 · 先跑起来

**目标**：能编译、能自检、能运行窗口，并能指着界面上任意一个数字说出它的来源。

## 1. 编译与自检

```bash
cd winformDemo
dotnet restore
dotnet build
dotnet run -- --self-test
```

`--self-test` 是 `Program.cs` 里特意留的开关：它**只构建 Host、解析服务，不创建任何控件**，把结果写到 `selftest.txt` 后直接退出。这是分层的第一个红利——业务层不需要窗口就能验证。

```csharp
// Program.cs
if (args.Contains("--self-test"))
{
    using var probe = builder.Build();
    var calibration = probe.Services.GetRequiredService<ICalibrationService>();
    var repository  = probe.Services.GetRequiredService<IMeasurementRepository>();
    var acquisition = probe.Services.GetRequiredService<AcquisitionService>();
    File.WriteAllText(..., $"OK | channels={calibration.ChannelCount} | ...");
    return;                       // 没有 Application.Run
}
```

📌 注意这里没有 `new`：所有对象都由 DI 容器创建，构造参数（配置、日志、其他服务）自动填好。

预期结果：`OK | channels=8 | repo=JsonMeasurementRepository | service=AcquisitionService | 通道1 raw=2700 -> 25.00 mm`

**如果失败**，按这个顺序查：

| 报错 | 原因 | 处理 |
|---|---|---|
| 找不到 `appsettings.json` | 没复制到输出目录 | 检查 csproj 的 `CopyToOutputDirectory`，`dotnet build` 后再看 `bin/Debug/net8.0-windows/` |
| 通道数不一致 | `ChannelCount` 与 `Channels` 数组长度不符 | `CalibrationService` 构造函数主动抛错，改 `appsettings.json` |
| RawHigh 必须大于 RawLow | 某个通道标定参数非法 | 改配置；这正是「启动即校验」而非「运行时算出 NaN」 |

## 2. 打开窗口，看数据怎么流动

```bash
dotnet run
```

窗口上有两块表格：上面 8 行是**实时通道数据**，下面是**历史记录**。每 500 ms 上面刷新一次，偶尔出现「合格 / 不合格」变化。

沿着一条数据走一遍（对照源码）：

| 步骤 | 代码位置 | 数据形态 |
|---|---|---|
| 1. 模拟设备产生 8 个 ushort | `Infrastructure/SimulatedModbusClient.cs` → `ReadChannelsAsync` | `ushort[8]`，例如 `[2700, 2683, ...]` |
| 2. 采集服务定时读取 | `Application/AcquisitionService.cs` → `ExecuteAsync` | `ushort[8]` |
| 3. 两点标定换算 | `Infrastructure/CalibrationService.cs` → `Convert` | `double`，例如 `25.00` |
| 4. 与上下限比较 | `AcquisitionService` → `qualified` | `bool` |
| 5. 打包成不可变记录 | `Core/Models.cs` → `ChannelReading` | `record` |
| 6. 发布事件 | `BatchArrived?.Invoke(batch)` | `IReadOnlyList<ChannelReading>` |
| 7. 表现层封送回 UI 线程 | `Presentation/MainForm.cs` → `OnBatchArrived` | `SynchronizationContext.Post` |
| 8. 写入表格 | `MainForm.RenderBatch` → `BindingList.ResetBindings()` | 界面上的一行 |

点「保存数据」后：

```
_latest → SampleRecord(DateTime.Now, 产品名, double[8])
        → IMeasurementRepository.AddAsync
        → JsonMeasurementRepository 写 samples.json
        → LoadHistoryAsync() 重新查询并刷新下方表格
```

📌 **值得停下来想一分钟**：从步骤 1 到 6，**没有一行代码知道界面是 WinForms**。第 7 步才第一次出现 `SynchronizationContext`。这条分界线就是企业级架构的核心。

## 3. 配置文件长什么样

```json
{
  "App": {
    "ChannelCount": 8,
    "SampleIntervalMs": 500,
    "StoragePath": "samples.json",
    "Channels": [
      { "RawLow": 2200, "RawHigh": 3200, "ValueLow": 20, "ValueHigh": 30,
        "LimitLow": 26, "LimitHigh": 28 },
      ...
    ]
  }
}
```

一个通道 6 个数：`RawLow/RawHigh`（传感器原始读数区间）→ `ValueLow/ValueHigh`（对应真实尺寸 mm）→ `LimitLow/LimitHigh`（合格判定区间）。通道1 的参数来自真实项目，所以你能在两套代码里看到同样的 `2700 → 25.00 mm`。

`samples.json` 是运行时生成的，已被 `.gitignore` 排除，不会进仓库。

## 🧪 动手实验

**实验 1.1 · 改采样周期**
把 `SampleIntervalMs` 从 `500` 改成 `100`，重新运行，观察刷新变快。再改成 `5000`，观察界面是否依然流畅（应该流畅，因为 UI 线程没有被阻塞）。

**实验 1.2 · 让所有通道都合格**
把通道1 的 `LimitLow` 改成 `0`、`LimitHigh` 改成 `999`，重新运行，观察「判定」列全部变成合格。改回来。

**实验 1.3 · 故意制造配置错误**
把某个通道的 `RawHigh` 改成等于 `RawLow`，运行 `--self-test`。观察 `CalibrationService` 抛出的异常信息，感受「启动时校验」和「运行时算出 Infinity」的区别。

**实验 1.4 · 保存并落盘**
点几次「保存数据」，然后打开 `bin/Debug/net8.0-windows/samples.json`，确认里面有你输入的产品名和 8 个数值。重启程序，确认历史记录还在。

## 自测

1. `--self-test` 为什么不需要 `Application.Run`？它验证了什么、没验证什么？
2. 界面上的「工程值 / mm」是谁算出来的？`MainForm` 自己算的吗？
3. 改 `appsettings.json` 后需要重新编译吗？为什么？

<details><summary>答案要点</summary>

1. 因为它只构建 DI 容器并解析服务，不创建控件；验证了配置绑定、依赖装配、标定计算，**没验证** UI 渲染和跨线程封送。
2. `CalibrationService.Convert()`，`AcquisitionService` 调用它；`MainForm` 只负责显示。
3. `reloadOnChange: false` 且配置在启动时读取，所以改完要**重启程序**；但不需要重新编译（配置是 `CopyToOutputDirectory` 复制的内容文件）。

</details>
