# 08 · 仓储与数据模型

**目标**：理解「不可变模型 + 仓储抽象」如何让持久化变成一个可插拔部件。

## 1. 模型：`record` 而不是可变类

```csharp
// Core/Models.cs
public sealed record ChannelReading(
    int Channel, ushort Raw, double Value, bool IsQualified, DateTime Timestamp);

public sealed record SampleRecord(DateTime Time, string ProjectName, double[] Values);
```

📌 `record` 给了三样东西：

1. **值相等性**：两个字段相同的 `ChannelReading` 用 `==` 比较为 true，便于测试和去重；
2. **不可变性**：位置参数生成 `init`-only 属性，跨线程传递不会被谁改掉；
3. **简洁**：`with` 表达式可基于已有记录创建变体。

对照旧项目 `dataModel`：8 个 `string dataN` 属性 + `string testTime`，数值以文本存 SQLite，导致：

- 排序 `ORDER BY testTime` 其实是字符串排序；
- 绘图时每次 `Convert.ToDouble`；
- 空串会让 `Convert.ToDouble("")` 抛异常；
- `Id` 界面与数据库各算一套，重启后重复。

本骨架里 `Value` 是 `double`，`Time` 是 `DateTime`，`Values` 是 `double[]`——**类型如实反映业务含义**。持久化时才由 `JsonMeasurementRepository` 负责序列化。

⚠️ `double[] Values` 是可变数组，严格来说不是完全不可变。教学骨架为了简洁保留它；生产代码建议换 `ImmutableArray<double>` 或 `IReadOnlyList<double>`。

## 2. 仓储接口：把「怎么存」挡在门外

```csharp
public interface IMeasurementRepository
{
    Task AddAsync(SampleRecord record, CancellationToken ct = default);
    Task<IReadOnlyList<SampleRecord>> QueryAsync(
        DateTime? from, DateTime? to, string? project, CancellationToken ct = default);
}
```

注意接口里**没有** `Save()`、`Flush()`、`OpenConnection()`、`ExecuteSql()` 这类实现细节。调用方只知道「加一条」「按条件查」。

`JsonMeasurementRepository` 的实现要点：

```csharp
private readonly SemaphoreSlim _gate = new(1, 1);   // 保护内存列表 + 文件写
private readonly List<SampleRecord> _items = new();

public async Task AddAsync(SampleRecord record, CancellationToken ct = default) {
    await _gate.WaitAsync(ct);
    try {
        _items.Add(record);
        await PersistAsync(ct);
    } finally { _gate.Release(); }
}
```

| 细节 | 为什么 |
|---|---|
| `SemaphoreSlim.WaitAsync(ct)` | 多个保存/查询并发时保护共享列表，且等待可取消 |
| `try/finally` 释放锁 | 即使写文件失败也不会把锁永久占住 |
| `Path.Combine(AppContext.BaseDirectory, ...)` | 与配置同目录，不受工作目录影响（第 05 章） |
| 启动时读文件用 `try/catch` | 数据损坏时降级为空集合并记日志，不让程序崩溃（对照旧项目 `Load<T>()` 返回 null 直接崩） |
| `QueryAsync` 返回 `ToArray()` | 返回快照，调用方改不了内部列表 |

📌 **仓储模式（Repository）** 的价值不是"少写 SQL"，而是**让业务层用集合的语义思考**，把事务、连接、序列化、索引都关在基础设施层。

## 3. 换成 SQLite 需要改什么（清单）

1. 新增 `SqliteMeasurementRepository : IMeasurementRepository`，注入 `IOptions<AppOptions>` 拿连接串；
2. 构造函数里 `CREATE TABLE IF NOT EXISTS` 建表（旧项目这里被注释掉了，是启动崩溃的根因之一）；
3. `AddAsync` 用参数化 `INSERT`，`QueryAsync` 用动态 `WHERE` + 参数；
4. 组合根把注册改成 `AddSingleton<IMeasurementRepository, SqliteMeasurementRepository>()`；
5. **其余 8 个 `.cs` 文件一个字都不用改**。

第 10 章会把这个作为毕业练习。

## 🧪 动手实验

**实验 8.1 · 验证落盘与重启**
点几次「保存数据」→ 打开 `bin/Debug/net8.0-windows/samples.json` → 确认结构与 `SampleRecord` 字段一致 → 重启程序 → 确认历史仍在。

**实验 8.2 · 让文件损坏，看降级**
把 `samples.json` 内容改成 `这不是 JSON`，重新运行。预期：程序正常启动、历史为空、输出窗口有 `LogError`。对照旧项目配置损坏时的 `NullReferenceException`。

**实验 8.3 · 并发保存**
把 `OnSaveClick` 临时改成连点：

```csharp
await Task.WhenAll(Enumerable.Range(0, 10)
    .Select(i => _repository.AddAsync(
        new SampleRecord(DateTime.Now, $"P{i}", _latest.Select(x => x.Value).ToArray()))));
```

运行，确认 `samples.json` 里有 10 条且 JSON 合法（`SemaphoreSlim` 起了作用）。做完还原。

**实验 8.4 · 换成内存仓储**
按第 04 章实验 4.2 写一个 `InMemoryMeasurementRepository`，改一行注册。运行：保存能刷新界面，但重启后历史消失。用这个实验体会「持久化策略」与「业务逻辑」确实是两件事。

**实验 8.5 · 加一个删除功能**
给 `IMeasurementRepository` 加 `Task DeleteAsync(DateTime time, CancellationToken ct = default)`，在两个实现里补上，再在界面加一个按钮调用。观察：**接口一改，所有实现类都要改**——这就是为什么接口要设计得小而稳定。

## 自测

1. 为什么 `QueryAsync` 的条件参数用 `DateTime?` 和 `string?`？
2. `SemaphoreSlim` 换成 `lock` 可以吗？有什么限制？
3. 「数据损坏时降级为空集合」是好事还是坏事？生产环境该怎么做？

<details><summary>答案要点</summary>

1. 可空表示「不按此条件过滤」，一个方法覆盖全量/时间/产品/组合查询；`QueryAsync(null,null,null)` 即查全部。
2. `lock` 不能跨 `await`（编译不过），而写文件是异步 IO；`SemaphoreSlim.WaitAsync` 支持异步等待与取消。
3. 对教学骨架是合理的可用性优先；生产环境应备份损坏文件、报警、并提示用户数据可能丢失，而不是静默清空后继续写（否则会把损坏覆盖掉）。

</details>
