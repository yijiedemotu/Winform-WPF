# 第一套：WinForms 企业级框架学习路线

> **学习顺序：先把本目录 `00` → `10` 全部学完，再进入 `../../wpfDemo/教程/00-学习路线.md`。**
> 两套 demo 是同一个业务（八通道尺寸测量），业务层代码逐字节相同，差别只在表现层。
> 一本一本学，不要跳：后面的章节默认你已经动手改过前面的代码。

## 这套要解决的真实问题

你之前看到的「项目学习」是典型的学习型代码：`static` 全局变量到处读写、`Task.Run` 里直接 `Invoke` 改控件、异常被空 catch 吞掉、8 个通道复制 8 遍、配置缺失就崩。它能跑，但**加功能会越来越难**。

这套骨架用同样的业务，重做一遍，目标不是"功能更多"，而是让你看清楚**企业级代码把复杂度放到了哪里**：

| 关注点 | 学习型写法 | 本骨架（企业级） |
|---|---|---|
| 全局状态 | `public static double[] data` | 不可变 `record` 在层间传递 |
| 硬件访问 | 页面里直接 `new ModbusRtuClient()` | `IModbusClient` 接口 + 容器注入 |
| 后台采集 | `Task.Run` + `while(true)`，从不取消 | `BackgroundService` + `CancellationToken` |
| 线程切换 | 后台直接 `Invoke` 改 TextBox | 服务发事件，表现层用 `SynchronizationContext` 封送 |
| 配置 | 分散的 json / 硬编码 8 | `appsettings.json` + 强类型 `IOptions<AppOptions>` |
| 存储 | 页面里直接拼 SQL | `IMeasurementRepository` 仓储抽象 |
| 启动装配 | 字段初始化器里到处 `new` | 唯一的组合根 `Program.cs` |
| 可测试性 | 必须开窗口才能验证 | `dotnet run -- --self-test` 无界面自检 |

## 环境

- Windows + .NET 8 SDK（本机是 10.0.402 SDK，带 8.0 桌面引用包，可直接编译 `net8.0-windows`）。
- NuGet 可访问（首次还原 `Microsoft.Extensions.Hosting 8.0.1`）。
- 不需要串口设备：`SimulatedModbusClient` 用正弦 + 噪声产生 8 路原始数据。

## 三条命令先跑通

```bash
cd winformDemo
dotnet restore
dotnet build
dotnet run -- --self-test     # 不弹窗口，验证配置/DI/业务层装配
```

自检会写出 `bin/Debug/net8.0-windows/selftest.txt`，预期：

```
OK | channels=8 | repo=JsonMeasurementRepository | service=AcquisitionService | 通道1 raw=2700 -> 25.00 mm
```

`25.00 mm` 来自两点标定：`20 + (2700-2200) × (30-20)/(3200-2200)`，和真实项目里通道1 的参数一致。

去掉 `--self-test` 直接 `dotnet run` 就会打开窗口，看到 8 个通道每 500 ms 刷新，点「保存数据」「刷新历史」可验证仓储。

## 目录结构（代码一共 9 个 .cs 文件）

```
winformDemo/
├── WinformDemo.csproj          项目与依赖
├── appsettings.json            强类型配置的来源
├── Program.cs                  ⭐ 组合根：唯一知道所有具体类型的地方
├── Core/                       领域层：不依赖任何框架
│   ├── Models.cs               ChannelConfig / AppOptions / ChannelReading / SampleRecord
│   └── Abstractions.cs         IModbusClient / ICalibrationService / IMeasurementRepository
├── Infrastructure/             基础设施层：实现接口，可替换
│   ├── SimulatedModbusClient.cs
│   ├── CalibrationService.cs
│   └── JsonMeasurementRepository.cs
├── Application/                应用层：编排，不依赖 UI
│   └── AcquisitionService.cs
├── Presentation/               表现层：只画界面
│   └── MainForm.cs
└── 教程/                       本套 11 篇
```

**依赖方向永远是单向的**：`Presentation → Application / Core`、`Infrastructure → Core`、`Application → Core`。`Core` 谁都不依赖。用编辑器全局搜索 `using System.Windows.Forms`，你会发现它只出现在 `Program.cs` 和 `Presentation/` 里——这就是分层是否被遵守的最简单检验方法。

## 每章的固定结构

1. **目标**：这一章结束你应该会做什么
2. **概念**：先讲清楚原理，不堆术语
3. **读代码**：给出具体文件与行，附关键片段
4. **🧪 动手实验**：一定有一个能立刻验证的小改动
5. **自测**：2~3 题，答案要点在章末
6. **对照**：与旧写法或另一套框架的对比

## 和下一套（WPF）的关系

学完本套后，进入 `wpfDemo`。那里你会做一件很震撼的事：

```bash
cd ../..
diff winformDemo/Core/Models.cs wpfDemo/Core/Models.cs
diff winformDemo/Application/AcquisitionService.cs wpfDemo/Application/AcquisitionService.cs
```

**全部无输出**。同一个业务、同一套服务、同一套配置，只把表现层从 `MainForm` 换成 `MainWindow + MainViewModel`。能理解这一点，你就真正理解了分层的价值。

> 记一句口诀：**表现层换框架，业务层不动一行。**
