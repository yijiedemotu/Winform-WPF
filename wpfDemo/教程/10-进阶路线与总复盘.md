# 10 · 进阶路线与两套总复盘（收尾）

**目标**：拿到一份「接下来学什么 / 做什么」的清单，并用总自测确认两套都学扎实了。

## 1. 两套总对照表（保存好）

| 维度 | `winformDemo` | `wpfDemo` |
|---|---|---|
| UI 描述 | C# `BuildUi()` | XAML 声明式 |
| 视图状态 | `MainForm` 私有字段 + `BindingList` | `MainViewModel` 属性 + `ObservableCollection` |
| 用户动作 | `Click +=` + `async void` | `IAsyncRelayCommand` + `{Binding ...Command}` |
| 数据绑定 | `DataSource` + `[DisplayName]` | `DataContext` / `ItemsSource` + `DataGridTextColumn` |
| 变更通知 | `IBindingList` + `ResetBindings()` | `INotifyPropertyChanged`（生成器）+ `INotifyCollectionChanged` |
| 线程封送 | `SynchronizationContext.Post` | `SynchronizationContext.Post`（**同一行代码**） |
| 生命周期钩子 | `OnFormClosed` | `Window.Closed` → `Unsubscribe()` |
| 组合根 | `Program.Main` | `App.OnStartup` |
| 启动 UI | `Application.Run(form)` | `window.Show()` |
| 关闭收尾 | `Task.Run(() => host.StopAsync())` | 相同 |
| Core / Infrastructure / Application | **逐字节相同** | **逐字节相同** |
| 配置 | `appsettings.json` | **逐字节相同** |

## 2. 企业级项目还缺什么（按优先级）

| 优先级 | 能力 | 说明 |
|---|---|---|
| 高 | 共享类库 | 把 Core/Infrastructure/Application 拆成 3 个类库，两套表现层用 `ProjectReference`（第 08 章实验 8.4） |
| 高 | 单元测试 | 标定、判定边界、仓储、取消、命令，都不需要窗口 |
| 高 | 日志落盘 | Serilog/NLog + 滚动，结构化字段 |
| 中 | 导航与对话框 | WPF 用 `INavigationService` / `IDialogService`，WinForms 用 Presenter；**绝不在 VM 里 `new Window()`** |
| 中 | 真实设备与数据库 | `NModbusClient`、`SqliteMeasurementRepository`（第一套第 10 章清单） |
| 中 | 报警/追溯/导出 | 不合格记录、CSV/Excel 导出、趋势曲线 |
| 中 | 配置热更新 | `IOptionsMonitor<T>` + `reloadOnChange` |
| 低 | 框架升级 | Prism（区域导航、事件聚合器、模块化）、ReactiveUI、MAUI 跨端 |
| 低 | 部署 | MSIX/ClickOnce、自动升级、多语言、DPI |

## 3. MVVM 常见坏味道自查表

| 现象 | 问题 | 改法 |
|---|---|---|
| ViewModel 里 `new MainWindow()` / 持有控件 | 反向依赖 | 用状态 + 命令 + 服务 |
| ViewModel 里 `MessageBox.Show` | 无法测试、绑死 UI | `IDialogService` 接口 |
| code-behind 里写业务判断 | 逻辑泄漏 | 移到 ViewModel / 业务层 |
| `Application.Current.Dispatcher` 出现在 VM | 绑死 WPF | `SynchronizationContext` 或 `IProgress<T>` |
| 静态 `ViewModelLocator` | 服务定位器反模式 | 构造函数注入 |
| 忘记 `-=` 取消订阅 | 内存泄漏 | `IDisposable` / Closed 钩子 |
| 后台线程 `ObservableCollection.Add` | 跨线程异常 | `Post` 到 UI 线程 |
| `{Binding}` 路径拼错 | 运行时静默失败 | 看 VS 输出窗口的绑定错误 |

## 4. 建议的三个毕业任务

**任务 A · 抽共享类库（必做）**
新建 `EnterpriseDemo.Core/Infrastructure/Application` 三个类库项目，把 6 个共享 `.cs` 移进去，两个表现层改为 `ProjectReference`，删除副本，两套都 `dotnet build` 通过。验收：`grep -R "System.Windows" EnterpriseDemo.*` 无输出。

**任务 B · 给两套同时加「连接状态」**
在 `AcquisitionService` 加 `event Action<bool>? ConnectionChanged`，两套表现层各自订阅并显示状态文字（WinForms 改 `Status`，WPF 改 `[ObservableProperty]` 属性）。验收：业务层只改一处，两个界面各自只改表现层。

**任务 C · 换成真实 SQLite 仓储**
实现 `SqliteMeasurementRepository`，只改组合根一行注册，两套程序同时生效，并且能读到彼此保存的数据。验收：WinForms 保存 3 条 → 打开 WPF → 历史里能看到这 3 条。

## 5. 总自测（两套综合，建议闭卷）

1. 说出四层的名字与依赖方向，并解释为什么 Core 不能引用 UI 框架。
2. 组合根做了哪三件事？为什么 `AcquisitionService` 要注册两次？
3. 依赖倒置在项目里体现在哪三个接口上？换真设备要改几个文件？
4. `BackgroundService` 相比 `Task.Run` + `while(true)` 多了什么？
5. `CancellationToken` 要传到哪些地方？漏传会怎样？
6. 为什么服务层只发事件、不直接调 `Invoke`/改集合？
7. `SynchronizationContext.Post` 在两套里分别是哪个具体类型？
8. `BindingList` 与 `ObservableCollection` 的通知粒度有何不同？
9. `ICommand` 相比 `Click +=` 多了什么能力？`CanExecute` 怎么用？
10. `[ObservableProperty]` 生成什么？为什么类要 `partial`？
11. `{Binding}` 写错为什么编译不报错？怎么排查？
12. 为什么 `OnExit` / `Program.Main` 都要用 `Task.Run` 包 `StopAsync`？
13. 为什么要取消事件订阅？两套分别在哪个钩子里做？
14. 两套共享哪 7 个文件？「零改动」靠什么保证、有什么隐患？
15. 把共享层抽成类库后，编译器能替你守住什么？
16. 数值/时间用 `string` 存储会带来哪些具体问题？
17. `appsettings.json` 的启动校验为什么比运行时算出 `NaN` 好？
18. 用一句话总结「企业级框架」对你意味着什么。

<details><summary>答案要点（提纲）</summary>

1. Core / Application / Infrastructure / Presentation，箭头单向指向 Core；否则无法复用与测试。
2. 注册服务、绑定配置、创建并启动宿主；单例供订阅 + 托管服务供生命周期，必须是同一实例。
3. `IModbusClient`/`ICalibrationService`/`IMeasurementRepository`；新增 1 个实现类 + 组合根 1 行。
4. Host 统一管理启停、提供 stoppingToken、可优雅停止、异常与 finally 可观测。
5. Connect / Read / Timer 等待；漏传会导致取消后仍要等一个周期甚至卡住退出。
6. 服务层不依赖 UI 框架，才能被两套表现层复用；线程语义交给消费者。
7. `WindowsFormsSynchronizationContext` / `DispatcherSynchronizationContext`。
8. 集合级 + 手工 ResetBindings（整表） vs 属性级自动通知（单元格）。
9. 复用、可用性（CanExecute）、异步与可测试；触发 `CanExecuteChanged`/`NotifyCanExecuteChanged()`。
10. 生成带通知的 public 属性；源生成器需要分部类注入代码。
11. XAML 是运行时字符串路径；看 VS 输出窗口 `System.Windows.Data Error`。
12. 避免 UI 线程同步等待时与 UI SynchronizationContext 死锁。
13. 单例事件强引用会导致泄漏与向已销毁对象 Post；`OnFormClosed` / `Window.Closed`。
14. Core×2、Infrastructure×3、Application×1、appsettings×1；靠复制 + diff，隐患是版本漂移。
15. 强制依赖方向（Core 引用 UI 直接编译失败）、单一副本、可被多前端引用。
16. 字符串排序不等于时间排序、每次要 `Convert.ToDouble`、空串抛异常、格式不统一。
17. Fail Fast：启动时给出明确错误，不会让错误数据流入判定与历史。
18. 用一组约束把变化局部化，使换 UI、换设备、换存储、加测试都只改一处。

</details>

## 6. 学习路线回顾

```
winformDemo/教程 00→10      建立分层、DI、后台服务、事件封送、仓储的完整心智模型
        ↓  diff 验证
wpfDemo/教程 00→10          把同一套业务层接到 MVVM 上，理解绑定/命令/Dispatcher
        ↓  毕业任务 A/B/C
共享类库 + 单元测试 + 真实设备/数据库
        ↓
能独立设计一个多前端、可测试、可维护的上位机解决方案
```

> 最后一句：**框架会换，分层不会。** 你在这两套里练的不是 WinForms 或 WPF 的 API，而是「把会变的东西关在门外」的能力。
